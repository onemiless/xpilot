## Contract counterexample (LO16)

The host must continue normal OEM+1 SP transmissions while a stock request is
pending. Panda may commit stock only when an OEM counter is last accepted SP+1.
With perfect 25 Hz OEM, every OEM instead equals the preceding SP counter.
All other gates and both acceleration endpoints are assumed valid and equal.

| Time (ms) | Input | Counter | Admission / owner |
|---:|---|---:|---|
| 10 | SP | 1 | admitted, owner SP |
| 11 | request STOCK | | pending |
| 40 | OEM | 1 | blocked; expected 2 |
| 50 | SP | 2 | admitted normally |
| 80 | OEM | 2 | blocked; expected 3 |
| 90 | SP | 3 | admitted normally |
| 120..250 | OEM / SP | continues | every OEM blocked, all SP retained |
| 261 | deadline | | pending cleared, owner remains SP |

`tools/sp_tesla_e2e/long_owner_check.py` first records the complete host failure
matrix LO1-LO16. Its executable portion models **LO16 only** at all ten integer
millisecond host phase offsets. Each phase expires; it returns **1**, keeping
the failed acceptance requirement visible. Every intervening SP frame remains
in the CSV. It guards against contract drift and identifies source hashes.
LO1-LO15 are explicitly NOT_RUN, not passing tests.

This agrees with X-48's L19 requirements reproducer. X-48's four requirements
checks returning 0 does not mean G8 liveness or firmware acceptance passed.
No host-only workaround was invented: withholding normal SP frames, accepting
a duplicate OEM counter, or changing the firmware handshake would alter the
agreed contract. The firmware files and wire contract were left unchanged.
